# B0 结构原型验证报告（2026-11-11）

点二「置信度先验 + 可学习主项软门控」的结构验证。**不含训练，不产生任何性能结论。**

## 一、结构

```
g   = sigmoid( alpha * logit(c_pair) + h(pool(R), pool(A)) )
R'  = R + g * P(A)
q   = UnifiedHead(R')          # 融合路径
q   = UnifiedHead(R)           # 拒配或仅可见光路径，g ≡ 0
```

- `P`：1×1 卷积，**零初始化**
- `h`：两层 MLP，**末层零初始化**
- `alpha`：可学习标量，初始 1.0
- 拒配：`g` 结构化置零，不是阈值

## 二、粒度一：合成张量（N=8, C=16, 8×8）

| 检查 | 结果 |
|---|---|
| 零投影等价 | 最大绝对差 **0.0**，`torch.equal` 为真 |
| 拒配后 g | 最大值 **0.0**，输出逐位等于 R |
| 门控单调性 | 非降，扫描 99 点最大步长 **0.0100** |
| 硬开关对照 | 0.5 处跳变 **1.0** |
| 梯度（初始） | 投影 **0.0508**；门控头 **0.0** |
| 梯度（投影更新一步后） | 门控头 **4.2e-05** |
| 统一头 | 零门控输出与 `head(R)` 逐位相同 |

**关键细节：门控头在第一步梯度为零。** 因为 `P(A)=0` 时 `dL/dg = dL/dR' · P(A) = 0`。这不是 bug，是零初始化的必然结果：投影先更新一步，门控从第二步才开始学。训练脚本必须知道这一点，否则会误判「门控没学」。

## 三、粒度二：真实权重 + 真实图像

用两侧冻结单模态检测器（`fold01_rgb` / `fold01_ir`），960 输入，抓检测头输入的第一张特征图（步长 8，实测 **65 通道**，120×120），按真值框 ROI 对齐到 7×7。

| 检查 | 结果 |
|---|---|
| 区域张量 | `R`、`A` 均为 `(6, 65, 7, 7)` |
| 真实特征零残差等价 | 最大绝对差 **0.0** |
| g 随 c_pair 单调 | 是（0.03→0.99） |
| 数值有限 | 是 |
| 拒配 g | **0.0**，输出逐位等于 `R` |
| 零初始化 h 时 g | 恒等于 **0.5**（= c_pair），跨区域标准差 **0.0** |
| 随机化 h 后 g | 跨区域范围 **[0.27, 0.41]**，标准差 **0.058** |

最后两行是这次验证里最有信息量的：**零初始化的 h 让 g 完全由 c_pair 决定，内容项确实"还没开始工作"；把 h 随机化后，同样的 c_pair 在不同区域给出不同 g，说明 h 的结构确实能读出内容差异。** 这是"可学习主项不是摆设"的最低限度证据——但仍然只是结构证据，不是训练后的行为。

## 四、两个需要注意的结构事实

1. **门控头第一步无梯度**（见上）。训练时应记录 `h` 的梯度范数，确认它在第二步之后才上升；若长期为 0，说明投影一直没离开零点。
2. **`alpha=1` + 零初始化 `h` 时 `g` 恒等于 `c_pair`**。这意味着 B0 在训练初期等价于"直接用点一的配对置信度当融合权重"。这既是好事（起点干净、可解释），也是陷阱（如果 h 学不动，B0 会退化成这个基线，且不易察觉）——所以要显式监控 `h` 的输出方差。
